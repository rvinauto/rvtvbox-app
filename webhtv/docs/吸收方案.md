## 2. 已完成的移植（可直接取用）

- 产物：`/workspace/_cmp/patches/merged-all-3-upstream-fixes.patch`（2252 行，16 文件，+1779/−157）
- 单提交补丁：`/workspace/_cmp/patches/{3f303174,c5b447b3,4e30ffaf}-*.patch`
- 合并树：`/workspace/_cmp/_probe`（detached worktree，**未创建任何 commit**）

三处冲突的解决口径：

1. `JarLoader.java` —— 上游把 `spiders × destroy + methods × close` 改成结构化清理；fork 已有 `SpiderCleanup.destroy` + `retireLoaders()`（translated runtime 下保活 DexClassLoader，防崩溃）。**保留 fork 结构，在 finally 里补 `methods.values().forEach(ProxyMethod::close)`**，让 `PanProxyCompat.close()` 真的被调用。
2. `mobile/LiveActivity.java` —— 三处：inset 回调、embedded 切换、recycler 插入位置。fork 版全胜（`Math.min(indexOfChild+1, childCount)` 比上游版本更防越界），**全取 ours**；只把上游在 `onPictureInPictureModeChanged` 里新增的 inset 刷新改名为 fork 的 `updateStatusBarInset(...)` 接上，并删掉上游带进来的重复方法。
3. `docs/E4-LIBASS-exo-ass-rendering.md` —— 取 fork 版。

## 3. fork 值得反向吸收的 7 个能力面

按"产品价值 ÷ 移植成本"排序，行数是 `app/src/main/java/.../tv/<包>` 实测。

| 能力面 | 规模 | 值不值得进主线 | 说明 |
|---|---|---|---|
| `subtitle/` 实时字幕（ASR+翻译+时间轴+注入） | 53 文件 / 6008 行 | **最值** | 上游完全没有；`RealtimeSubtitle*` 一套模型目录/校验/缓冲/翻译分层干净，是 fork 的核心差异 |
| `service/` AI 服务层（AI 广告检测、季集识别、标题提取、日志诊断） | 23 文件 / 11818 行 | **值** | 唯一有"AI 增强"落地的地方，且拆成独立 client，可单点关 |
| `server/proxy/` 多线程代理（Range/有序块/能力令牌/域规则） | 22 文件 / 3828 行 | **值** | 比上游内置代理抗并发，`HttpByteRange`/`OrderedChunkBuffer` 是可复用件 |
| `plugin/` 插件框架（能力注册、审计、bundle 索引、QuickJS） | 30 文件 / 7432 行 | 值 | 依赖 `:nodejs` + quickjs，是重资产；只有做插件生态才拿 |
| `cache/` 缓存中心（清理策略/日志/可用性） | 34 文件 / 2431 行 | 值 | 小而全，低耦合，适合先拿 |
| `playback/` 播放进度同步（身份/别名/tombstone/批量） | 30 文件 / 4826 行 | 值 | 比上游 serverless 身份注册表（epoch/aliases）实现更贴客户端语义 |
| `lab/` 调试台（命令面板、文件浏览、环境） | 24 文件 / 7487 行 | 调试用，不进正式包 | 保留在 fork，别污染 release |
| `theme/` 29 文件 5566 行、`web/` 37 文件 10580 行、`tts/` 14 文件 2718 行 | — | 可选 | `tts` 依赖 `commons-compress`/`tukaani-xz`；`web` 是 Web 首页桥，和我们的 webhtv 前端强相关，单独评估 |

fork 另外三个**工程习惯**层面的优点，比代码更值：

1. `docs/` 469 份任务文档 + 评估账本，改动能追到"为什么"；上游 `e519fdef` 恰好相反（文档不入库）。我们的项目该学 fork，但放独立分支/私有仓，别压主包。
2. `settings.gradle` 加了阿里云镜像（`gradle-plugin`/`public`/`google`），国内出包成功率明显提升；`app/build.gradle` 加 `work-runtime`、`commons-compress`、`tukaani-xz`、`fileTree` 收 `*.jar`、`androidTest.assets` 挂 `schemas`（Room schema 可测）。
3. `testImplementation libs.junit` + `androidTest` 侧 5 个 ASS 测试（`AssNativeGoldenTest`/`AssPlaybackTest`…），上游没有这层。

## 4. 落地顺序（三步，每步可独立回滚）

1. **补上游 3 修复**（已完成）：`cd <fork> && git am -3 /workspace/_cmp/patches/merged-all-3-upstream-fixes.patch`，或按单提交 `git cherry-pick 3f303174 c5b447b3` + 手工 `4e30ffaf` 的 PIP 一行。
2. **补阿里云镜像 + test 依赖**：从 fork `settings.gradle`/`app/build.gradle` 摘 6 行，先解决出包问题再谈功能。
3. **按表逐个搬包**：`cache → server/proxy → subtitle → service`，每搬一个跑一次 `assembleMobileArm64_v8aRelease`，搬不动就停，别一次拉 `plugin`/`nodejs`。

## 5. 明确不做

- 不把上游 `e519fdef` 的"文档不入库"反向套到 fork（会丢 469 份资产）。
- 不整包 merge 上游（7 个提交里 3 个是文档、1 个被 fork 超越，只有 2 个有代码价值）。
- 不把 `lab/` 带进 release 包。
